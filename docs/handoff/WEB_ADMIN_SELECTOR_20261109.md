# WEB 구분 선택기 — 어드민 연결

2026-11-09 사용자 요청: 기존 고객 대표·내부 사용자·딜러 대표 등이 있는 상단 구분 선택기에, 만들어 둔 어드민 화면을 연결한다. GitHub 공개본에서는 어드민 구현이 아직 빠져 있었고 로컬 구현은 완료되어 있어 검토한 구현을 선별 반영한다.

## 연결

- 구분 목록의 기존5항목을 유지하고 `어드민`을 추가한다. 공통 계정 역할은5개 그대로이며 WEB 시안의 진입 문맥은 `role=internal&portal=admin`이다.
- 어드민 선택 → `web/Admin/customer-management.html`. 일반 구분 선택 → 해당 구분의 기본 대시보드로 복귀하고 admin 포털·다른 역할의 업체/그룹/차량 조건은 제거한다.
- 어드민 GNB는 권한관리 / 현황관리 / 운영관리다. 권한관리의 고객/딜러 선택과4/3개 상세 탭, 인터페이스·Alert, 기존 운영관리8페이지를 연결한다. 미정 현황 항목은 비활성으로 유지한다.
- 기존 페이지 ID ADM001~010, ADM012/013과 하위 목적 ID를 유지한다. ADM011·새 공통 계정 역할을 발급하지 않는다.

## 범위와 실행

신규 Admin HTML4개·공유 자산9개, nav/Operations core/기존 CSS2개의 어드민 확장, 기존 GNB33페이지의 helper·캐시 참조를 반영한다. Operations8페이지는 기존 제작본의 포털 breadcrumb·메뉴 명칭도 유지한다. 그 외25페이지의 본문·데이터·디자인은 변경하지 않는다.

기존에 사용자가 요청한 좁은 창의 메뉴 열기/닫기 버튼 수정도 유지한다. 버튼을 실제 LNB/layout 경계에 붙이며 기존 모양과 일반 폭 위치는 같다. 새 observer/renderer를 덧붙이지 않는다. 이전 `admin-monitoring.js`는 배포하지 않는다.

현재 공개본의 한국어 게시 프로필·계정/로그인·공통 데이터·대시보드2탭·운영효율 변경을 유지한다. 로컬의 별도 로그인 복구·인증 변경, 비교안/백업·미사용 자산을 통째로 가져오지 않는다. 화면 전환용 선택기는 시안의 역할 전환이며 실제 서버 계정 권한을 변경하지 않는다. Admin 데이터 조작도 기존 브라우저 예시 원장을 사용한다.

## 검증

- 격리 게시본 브라우저42개 검사: 기존5구분→어드민→원래구분,6개 옵션,3개 GNB,12페이지와 포털 링크, 고객/딜러4/3탭, 미정 비활성, 직접 비어드민 진입 차단, 일반GNB25페이지의 옵션 유지. 콘솔 오류/자산404 0건.
- 기존 대시보드15px/216px·종합/그룹2탭 유지. 한국어 출시에 불필요한 i18n runtime/AS-IS 참조는 포함하지 않는다.
- 같은1440px·같은 기준 시각으로 공개 원본과 후보 메인의 배치·본문을 비교해 동일함을 확인했다. 어드민 옵션은 선택 목록에만 추가한다.
- 원본 WEB 검사44페이지/176런타임 자산·생성 원본 일치, 직접 실행한 관련17개 기존 검사 통과.
- GitHub Pages 게시 후 실제 선택기 전환과12페이지·자산 바이트 일치를 별도로 확인한다. AWS·실제 Vue/API/DB·모바일·Figma/FigJam은 이 게시 작업의 변경 대상이 아니다.
