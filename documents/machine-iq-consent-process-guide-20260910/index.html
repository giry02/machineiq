MACHINE IQ 차량·권한·동의 프로세스

생산 시점에 생성된 차량과 단말 정보가 MACHINE IQ에 들어와 차량으로 매핑되고, 고객 동의와 승인 여부에 따라 조회 가능한 차량 범위로 확정되는 과정을 설명합니다. 전체 흐름과 FigJam의 각 세부 공정을 같은 번호 체계로 연결했습니다.

실선 화살표

업무가 진행되는 주 경로입니다. 왼쪽 단계의 처리 결과가 오른쪽 단계의 입력으로 넘어갑니다.

회색 점선

공정 이동이 아니라 해당 단계의 데이터 정의를 연결합니다. 점선 끝의 표는 화면이나 API의 다음 단계가 아닙니다.

논리명

업무 담당자가 이해하는 데이터 이름입니다. 예: 차량, 단말, 동의 상태, 승인 요청.

물리명

API·DB에서 구현 시 사용하는 후보 필드명입니다. 실제 확정 명세와 다르면 연계 설계 단계에서 조정합니다.

세 가지 관계를 구분해야 합니다

① 차량–단말 관계는 “어떤 단말이 어떤 차량에 장착됐는가”, ② 업체–차량 관계는 “누가 이 차량을 소유·판매·서비스하는가”, ③ 동의–권한 관계는 “누가 어느 기간 동안 이 차량 데이터를 볼 수 있는가”를 의미합니다.

전체 01

전체 공정: 생산에서 화면 조회와 서비스 처리까지

세부 공정이 어느 위치에 속하는지 먼저 설명하는 상위 지도입니다. 전체 단계를 5개 구간으로 묶되, 실제 공정은 01~14단계로 유지합니다.

① 생산·원천 기준정보MES/MQS에서 생산 결과, ERP/SAP에서 차량·판매 기준정보 생성
② 단말 수집·검증·차량 매핑단말 최초 신호 수신, 필수값 검증, 차량·단말 기준정보 조회
③ 관계·운행 데이터 적재차량–단말 유효 관계와 통신·위치·운행·에러 이력 저장
④ 동의·권한 판단사용자 조직·역할과 동의·승인 상태를 확인하여 허용 범위 산정
⑤ 조회·서비스 처리허용된 차량만 화면에 표시하고 조치 결과와 변경 이력을 저장
이 장에서 강조할 핵심

단말 데이터가 들어왔다고 바로 사용자 화면에 노출되는 것이 아닙니다. 차량 식별 → 관계 확정 → 동의·권한 확인 → 조회 범위 계산을 모두 통과해야 합니다.

세부 03

미동의·만료·권한 불일치: 조회 제한과 다음 행동 안내

차량 후보는 확인됐지만 유효한 동의나 승인 조건이 부족한 경우입니다. 단순 오류가 아니라 “왜 제한됐는지”와 “다음에 무엇을 해야 하는지”를 결과로 반환합니다.

Y · 동의 유효

이 세부 공정에서 종료하지 않고 세부 04 동의 차량 처리로 연결합니다.

N · 동의 없음 또는 무효

제한 상태를 저장하고 동의 요청, 승인 대기, 갱신 등 다음 행동을 안내합니다.

  1. 사용자가 업체와 차량을 선택하면 요청자 정보까지 포함한 매핑 요청이 생성됩니다.
  2. MIQ는 먼저 해당 차량의 기존 소유·판매·사용 관계를 확인합니다.
  3. 관계가 있다고 곧바로 허용하지 않고, 동의 상태·범위·만료 여부를 따로 검사합니다.
  4. 조건이 부족하면 제한 사유를 코드화해 저장하고, 화면에는 필요한 다음 행동을 함께 반환합니다.
  5. 따라서 “차량을 찾지 못함”과 “차량은 있으나 볼 권한이 없음”을 서로 다른 상태로 안내할 수 있습니다.

세부 04

동의·승인: 활성 관계 저장과 조회 범위 반영

세부 03 제한 처리로 이동하여 미동의·만료·권한 불일치 사유를 반환합니다.

판단 기준

승인 행위자가 해당 조직 범위를 처리할 권한이 있는지, 고객 동의가 유효한지, 업체–차량–사용자 관계의 유효기간이 현재 시점에 포함되는지를 모두 충족해야 합니다.

세부 05

가입·승인·수동 보완

자동 매핑만으로 해결되지 않는 계정 생성, 고객 동의, 딜러 승인, 장비 식별 보완을 처리하는 보조 공정입니다.

A. 회원가입 및 자동 승인

  • 고객이 사업자번호·업체명·연락처를 입력합니다.
  • Web이 사업자번호와 차량 보유 관계를 검증합니다.
  • 관계가 일치하면 자동 승인하고 사용자·업체·역할·그룹 범위를 생성합니다.
  • 불일치하면 반려 사유와 보완 자료를 관리하는 승인 대기로 전환합니다.

B. 고객 동의 및 차량 승인

  • 소유자 계정과 처리 딜러를 선택하고 약관에 동의합니다.
  • 차량 권한 신청 후 딜러 승인 완료 여부를 확인합니다.
  • 승인 시 관계 유효기간을 저장하고 동의 고객의 차량 목록을 재조회합니다.

C. 수동 매핑 보완

  • Equipment ID가 불명확하면 단말 시리얼 사진 등 증빙을 접수합니다.
  • 운영자가 SAP/MES/MIQ 기준정보를 대조해 실제 장비와 단말 일치 여부를 확인합니다.
  • 일치하면 수동 관계를 저장하고, 불일치·중복은 보완 사유와 처리 상태를 남깁니다.

설명 시 분리할 항목

  • 가입 승인과 차량 조회 승인은 같은 승인이 아닙니다.
  • 약관 동의와 차량 데이터 제공 동의의 버전·범위를 별도 관리해야 합니다.
  • 수동 보완은 자동 공정의 예외이며 정상 경로로 설명하면 안 됩니다.

Q&A

설명 자리에서 예상되는 질문

현재 FigJam의 의미를 설명하기 위한 답변이며, 실제 운영 정책과 물리 테이블은 확정 과정에서 달라질 수 있습니다.

Q1. 차량과 단말이 매핑됐으면 바로 화면에서 보이나요?
아닙니다. 차량–단말 관계는 데이터 귀속을 위한 물리 관계입니다. 사용자가 보려면 업체·사용자 관계와 유효한 동의·승인 조건까지 충족해 허용 차량 집합에 포함돼야 합니다.
Q2. “미동의”는 차량을 못 찾았다는 뜻인가요?
다릅니다. 차량을 못 찾는 경우는 식별·매핑 실패이고, 미동의는 차량 또는 관계 후보는 있으나 데이터 조회 근거가 부족한 상태입니다. 화면 안내와 후속 조치도 별도로 처리해야 합니다.
Q3. 동의만 있으면 누구나 승인할 수 있나요?
아닙니다. 승인 행위자가 해당 조직·고객·차량을 처리할 권한이 있어야 하고, 동의 범위와 유효기간도 현재 요청에 맞아야 합니다.
Q4. 동의가 만료되거나 철회되면 어떻게 되나요?
활성 관계의 유효 상태를 변경하고 허용 업체·그룹·차량 집합을 다시 계산해야 합니다. 이후 조회는 제한 경로로 전환되고 만료 또는 철회 사유와 필요한 행동을 반환합니다.
Q5. D31~D45는 새로운 공정 번호인가요?
아닙니다. P31~P36 또는 ①~⑥은 처리 단계이고, D31~D45는 그 단계 옆에 붙는 데이터 정의 ID입니다. 데이터 표는 공정 경로에 포함되지 않습니다.
Q6. 왜 논리명과 물리명을 같이 표시하나요?
업무 담당자는 “승인 대상·동의 상태·조회 범위”로 이해하고, 개발 담당자는 실제 API·DB 필드로 연결해야 하기 때문입니다. 같은 데이터를 두 관점에서 확인하기 위한 표기입니다.
Q7. 자동 매핑이 실패하면 데이터가 유실되나요?
즉시 유실로 처리하지 않습니다. 요청 이력과 실패 사유를 남기고 재조회·재호출·수동 보완 경로를 거치도록 설계합니다. 단, 재시도 주기와 최대 횟수는 운영 정책으로 확정해야 합니다.
Q8. 현재 표의 물리 필드와 테이블명이 최종 확정인가요?
FigJam에서 데이터 흐름을 이해하기 위한 연결 기준입니다. 실제 API 스키마와 DB 명세 대조 후 필드명, 기준 시스템, 저장 테이블, 이력 보존 방식은 최종 확정해야 합니다.
